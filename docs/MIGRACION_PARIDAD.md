Esta matriz se basa en los manuales y suites vigentes del PHP de origen y en rutas, controladores, servicios, modelos, migraciones y pruebas del Laravel actual. “Migrado” requiere comportamiento equivalente y pruebas pertinentes; el mero hecho de que exista una página o clase no basta. Los resultados históricos del repo fuente son evidencia del origen, no pruebas de Laravel.

## Reglas de alcance del origen

- Los trámites nacen presencialmente en Mesa de Partes. El estudiante consulta sus propios expedientes y confirma recepción; no inicia un trámite web ni carga correcciones.
- No forma parte del alcance actual una app móvil, OCR, IA o firma digital/biométrica.
- Los bloques B1–B7 del origen aparecen como completados y probados en `docs/ESTADO_ACTUAL_PROYECTO.md`; los resultados de esas suites no certifican la implementación Laravel.
- El origen deja formatos institucionales reales y configuración operativa real como pendientes. Debe contrastarse `docs/AUDITORIA_PRE_B8.md` y `docs/CONFIGURACION_FINAL_PRE_DEPLOY.md` antes de declararlos paridad requerida.

## Evidencia de conexión y límites de las pruebas

- La lectura `SELECT 1` y el esquema de Turso fueron confirmados previamente por el usuario; no prueban escrituras, transacciones ni concurrencia.
- `phpunit.xml` establece SQLite en memoria para pruebas ordinarias. Las pruebas Turso de `TramiteWorkflowTest.php` y `TursoConnectionTest.php` cambian expresamente a `libsql`; ahora requieren `TURSO_TEST_DATABASE_URL`, `TURSO_TEST_AUTH_TOKEN` y `TURSO_TEST_DATABASE_DISPOSABLE=true`. El helper rechaza el mismo endpoint normalizado de la conexión de aplicación; el proceso hijo de concurrencia también rechaza compartir host.
- No ejecutes las pruebas Turso hasta contar con una base de prueba desechable identificada. Mantén `.env` privado y nunca imprimas sus valores.
- PHP CLI 8.5 ya está disponible. `php artisan test --compact` pasó: 68 pruebas, 62 aprobadas, 6 omitidas, 538 aserciones y 2 avisos sin detalle del runner. `php artisan test tests/Feature/Database/TursoConnectionTest.php --colors=never` pasó con 7 pruebas simuladas, 2 omisiones remotas y 1 aviso sin detalle. La prueba real de Turso sigue bloqueada por ausencia de `TURSO_TEST_*` y base desechable confirmada.
- `config/cache.php` conserva archivos como almacén predeterminado del limitador, pero acepta `CACHE_LIMITER`; `phpunit.xml` usa `array` para aislar la cuota de pruebas. `php artisan test --compact tests/Feature/Settings/SecurityTest.php` pasó 5/5 después de este ajuste.
- `pnpm run build` pasó en la etapa de búsqueda; `pnpm run types:check`, `vendor/bin/pint --dirty --format agent`, `git diff --check` y el chequeo focalizado de los cinco archivos frontend nuevos/tocados pasaron. `pnpm run check` global sigue fallando por formato en 32 archivos del worktree actual, incluida esta matriz y pantallas con cambios concurrentes ajenos a la reconciliación documental; no se hizo formato masivo. PHPStan con 512 MB informa 434 errores globales, incluidos tipos Eloquent existentes y tres diagnósticos en el nuevo comprobante; el controlador de búsqueda y el comando CLI pasaron PHPStan focalizado sin errores. No se ha corregido la línea base estática del proyecto.
- La verificación pública falló inicialmente con HTTP 500 porque su ruta excluía la sesión pero Laravel 13 intentaba emitir una cookie CSRF; la ruta GET ahora excluye también `PreventRequestForgery`. Tras compilar assets con `pnpm run build`, sus 3 pruebas pasaron. Esta corrección no habilita acceso al PDF privado.
- Si se pierde la respuesta del commit de reserva, puede quedar un documento `generando` con el correlativo consumido. El índice vigente bloquea otra reserva y el comando CLI permite inspeccionarlo y cerrarlo como `fallido` sin reutilizar el número; no reanuda la generación con el mismo número. Si se pierde la respuesta del commit de emisión, el servicio intenta comprobar estado persistido e integridad del PDF; si no puede probar éxito, conserva la reserva y el archivo. Si la respuesta del cierre CLI se pierde, repetir la inspección o `--fail` es idempotente en SQLite. Estas pruebas locales simulan cortes mediante eventos de transacción de SQLite y no demuestran el comportamiento del protocolo Turso ante una pérdida real de respuesta. Los archivos privados huérfanos después de una interrupción previa al commit requieren una limpieza operativa controlada.

## Próximos pasos por prioridad

2. En un entorno autorizado, crear/usar una base Turso desechable y probar driver: valores preparados, IDs, FKs, DDL, rollback/commit, concurrencia, timeout y resultado ambiguo.
3. Demostrar reserva y cierre CLI con escrituras concurrentes y respuestas ambiguas en Turso desechable; definir si la reserva `generando` necesita reanudación con el mismo número además del cierre seguro como fallida.
4. Generar QR con URL basada en `APP_URL`, incorporarlo al PDF y probar lectura real; luego implementar anulación/sustitución con autorización y auditoría.
5. Completar módulos funcionales restantes según las filas de esta matriz, uno por uno, con permisos y pruebas específicas.
6. Auditar las dependencias e imports UI Radix/Base UI después de conservar el comportamiento y pasar checks.
7. Optimizar consultas solo después de pruebas de paridad y evidencia de rendimiento.
